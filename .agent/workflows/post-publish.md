# 블로그 게시글 작성 및 SEO 검수 워크플로우

홈페이지 전담 **수항사**는 새로운 게시글을 작성하고 배포할 때 다음 단계를 엄격히 따릅니다.

## 1단계: 콘텐츠 생성 및 구조화

- `content/posts/[post-name]/index.md` 구조(Page Bundle)를 생성합니다.
- 관련 이미지는 모두 해당 폴더 내에 위치시킵니다.
- 제목, 설명, 카테고리를 설정합니다.

## 2단계: SEO 및 템플릿 검수 (필수)

// turbo

1. **태그 및 키워드 일치성 확인**: `tags`와 `keywords` 목록이 서로 보완적이며 핵심 단어를 공유하는지 확인합니다.
2. **네이버 최적화**: `description`의 길이를 체크합니다 (80자 미만 권장).
3. **내부 링크 추가**: 관련 있는 이전 포스트를 2개 이상 찾아 **[함께 읽으면 좋은 글]** 섹션에 추가합니다.
4. **선장님의 서명**: 글 마지막에 **"Bon Voyage!"** 문구가 포함되었는지 확인합니다.

## 3단계: 기술 검증 및 금기 사항 체크 (Technical Audit)

// turbo

1. `hugo` 명령어를 실행하여 빌드 오류가 없는지 확인합니다.
2. **[금기 2 체크]** 생성된 `public` 폴더의 HTML 파일에서 `localhost` 문자열이 남아있는지 샅샅이 검색합니다.
3. **[금기 1 체크]** 리소스 경로 변경 시, 옛 주소를 네이버 등에 삭제 요청할 목록을 정리합니다.
4. 이미지 경로가 절대 경로가 아닌 상대 경로(예: `IMG_1234.jpg`)로 정상 렌더링되는지 확인합니다.

## 4단계: 보고 및 배포 (Deployment & Error Fix)

1. **깃허브 푸시**: `git add`, `commit`, `push`를 순차적으로 진행합니다.
2. **에러 모니터링**: 배포 중 에러(Merge conflict, 권한 문제, 경로 오류 등) 발생 시 즉시 로그를 분석합니다.
3. **자가 수정**: 발견된 에러를 바탕으로 코드를 수정하거나 깃 설정을 조정하여 재배포를 시도합니다.
4. **최종 확인**: 라이브 사이트(myyacht.kr)에 접속하여 변경 사항이 정상 반영되었는지, 404 에러나 `noindex` 잔재가 없는지 확인한 후 선장님께 보고합니다.
