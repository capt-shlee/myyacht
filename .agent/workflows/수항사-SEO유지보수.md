# SEO 유지보수 및 404/색인 리스크 관리

이 문서는 네이버 서치어드바이저 + 구글 서치콘솔 운영 기준입니다.

## 1. 기본 정책

- `tags taxonomy`는 비활성화 상태를 유지합니다.
- 삭제된 URL은 `404 유지`가 원칙입니다.
- `/tags/*`는 새로 살리지 않습니다.
- `robots.txt`로 전체 차단하지 않습니다. (필요 URL만 처리)

## 2. 정기 점검 루틴 (주 2회)

1. 아래 자동 점검 실행

```powershell
.\scripts\seo-preflight.ps1 -BaseUrl https://myyacht.kr
```

2. 네이버 서치어드바이저 확인
- 새로 추가된 404 URL만 선별
- 이미 요청한 URL과 중복 요청하지 않기
- 상태코드가 실제 404인지 먼저 확인 후 검색제외 요청

3. 구글 서치콘솔 확인
- "페이지 색인 생성 제외" 리포트에서 신규 항목만 확인
- 의도된 404는 유지, 의도되지 않은 URL만 원인 추적

## 3. SERP 메타 품질 가이드

- `title`: 한글 18~32자 권장 (최대 40자)
- `description`: 한글 70~95자 권장 (최대 120자)
- 브랜드 키워드 1~2순위 고정: `마이요트`, `제부도요트`
- 중복 설명/중복 제목 과다 발생 시 우선 수정

## 4. 점검 시 즉시 수정 대상

- 포스트 front matter의 `tags:`
- 소스 또는 생성물의 `localhost`, `127.0.0.1`
- `sitemap.xml` 내 `/tags/` 포함
- 레거시 폐기 URL가 404가 아닌 200/301로 변한 경우

## 5. 변경 후 후속 작업

- 배포는 `safeship.ps1` 우선
- 배포 후 핵심 URL 상태 재확인
- 네이버/구글 수집 요청은 변경된 URL만 최소로 실행
